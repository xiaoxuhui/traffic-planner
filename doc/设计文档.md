# 路流 · 设计文档

版本 0.1.0；状态：实施中；策略：领域模型 → 仿真 → 界面 → 浏览器验证。

## 设计目标
1. 用户能看懂道路方向、车流入口和出口以及灯的状态。
2. 编辑即时可见，无存档默认空图，示例按需载入，手机也能完整操作。
3. 道路、寻路与车辆规则不依赖 DOM，可用 Node 原生测试验证。

## 分层
- `src/core.js`：UMD 纯模型。整数网格节点、邻接有向边、BFS、验证与序列化。
- `src/simulation.js`：固定步长仿真，队列、信号灯、交叉口占用锁、统计。
- `src/app.js`：状态协调、编辑历史、SVG 渲染、指针与键盘输入、持久化。
- `styles.css` / `index.html`：深色控制台 + 绿色规划地图，图标采用内联 SVG；无网络字体与外部运行依赖。

## 数据
`{version:1, roads:[{a:'x,y',b:'x,y',dir:'both'|'forward'|'reverse'}], sources:[{node,target}], exits:[node], signals:[{node,cycle,offset}], demand}`。
每条边只连接相邻网格点。规范化端点后保存方向。删除孤立节点时同时清理附属设施。导入严格验证数量、坐标、相邻关系、方向、引用与取值范围。v1 的 target 字段保留为兼容占位，读取旧存档时清空，新车不使用它固定出口。

## 仿真
BFS 沿有向邻接图一次遍历，收集每个入口到所有可达出口的最短路线。每辆新车独立等概率抽取一条出口路线，等待发车空间期间保留已选路线，避免排队重抽造成偏向。随机源默认 Math.random，可在测试中注入确定序列。入口按 demand 设定尝试发车，受首段空间限制，不可达则不发车。0.7 为停止线；交叉口有独占锁，车辆离开路口一段距离后释放。同一有向边的车辆保持最小间距，驶入已满的下一段时不进入路口。信号灯东西/南北交替，各绿灯后有 1 秒全红。统计记录到达数、在途数、停车数、平均旅行时间；仿真是教学近似而非工程交通预测。

## 交互
工具：选择、画路、方向、信号灯、入口、出口、删除。SVG 使用透明点击节点与道路命中层，线路箭头持续可见。画路支持拖动或两次点击、Escape 取消。右侧检查器展示入口可达出口数与随机分流说明，可编辑道路方向、灯周期。入口选中时虚线展示全部可达出口路线。历史最多 60 项。路网编辑自动暂停，避免旧路径引用。

## 失效处理
localStorage 失败时提示并保留内存状态；导入最多 1MB 且严格验证。空图与不可达入口给出引导。预览服务绑定 localhost，限制路径穿越。构建仅复制白名单源文件到 dist。

## 空白地图修正（2026-10-21）
移除场景装饰层及画布中央空态卡片。空态说明显示在地图上方标题副文案，画布仅保留网格。新建空图按钮位于地图工具栏，在窄屏也可见，并自动选择绘制道路工具。存储缺失或损坏均使用 `empty()`，保持有效存档恢复行为。

## 验证
`node --test` 验证领域行为与结构，`node scripts/build.js` 验证构建。真实浏览器检查绘路、方向、灯、来源目标、运行/暂停、保存恢复与移动布局，保存截图与测试报告。

## 立交桥与行驶方向（2026-10-21）
v1 数据增加可选 `bridges:[{node,over:'ew'|'ns'}]`，旧存档缺字段视为空。四向十字点可加桥，桥处只能同轴直行，禁止转弯与掉头；入口出口不放在桥的跨线点，建桥时移除该点的平面信号灯。删路导致不再四向时清除桥，拆桥保留道路并恢复平交。

## 用户控制绘制与线路
道路绘制增加 crossing 参数 over / under / connect。中途直行跨过既有垂直道路，自动分层；路径端点作为显式连接点，解除该点跨线。普通模型 API 默认 connect 维持原调用兼容，界面默认 over。

v1 增加可选 routes 数组，每项 `{nodes:[...]}`，保存从入口到出口的完整相邻节点序列。路线形状校验与可通行校验分开：因删路或改方向造成不可行的路线仍保存，避免刷新时丢失用户指定意图；运行时跳过不可行路线，并且有用户路线时不退回 BFS。入口被删除时才清理对应路线。画路线不调用 BFS 进行隐藏绕行，逐段检查有向边及跨线规则，禁止立即掉头。入口可有多条路线，按不同出口分组后等概率选择出口，再选择该出口的一条指定路线。

## 发车停止修复
旧准入阈值只要求前车在下一段的 p≥0.47，却允许后车跟到 p=0.26；后车需要 p≥0.30 才释放上一处路口，从而形成互锁。准入空间统一要求跟车间距 GAP + 路口释放距离 CLEARANCE + 本步移动量，保证进入路口后能驶到释放点。

用户进一步说明是局部堵塞。旧全局 180 辆上限会把仍有空位的入口也停发，故移除全局数量准入门槛。每个入口独立检查其发车间隔、规划路线和首段车道间距；其他入口的拥堵不直接禁止它发车。界面明确列出正在等前车腾位的入口，不把局部等待显示为全图停发。

## 分流道路参与自动选路
自动队列形成闭环时，每 0.5 秒检查停在路口前的车头依赖环；只在每段一辆待行车辆、所有目标路口互不冲突且绿灯/未被占用时同步预约，车辆仍沿原路线前进。

2026-10-24 死锁修正设计：上述单车限制扩展为实际等待依赖，包括同车道前车、下一车道队尾及尚未驶离路口的持锁车辆。发现闭环后，检查车头目标路口互异、信号放行、全部阻挡车在闭环内及跨路段车距，再协调预约车头。旧持锁车已经进入出向道路时才可交接，后续车头持续检查旧车位置，在旧车完全离开路口前不能抵达节点；其它来向继续让行。所有已预约车辆也检查下一段车尾距离，使腾位按实际空间逐步传播，避免进入下一段时追尾。入口合流让已预约的过路车辆先行，不能突然发车插到它前面。路线与目的地保持；正常排队与红灯等待不触发强行放行。

## 示例库
独立 examples 模块依赖 core，提供六份案例描述及每次重新创建的模型，不共享可变数据。全部案例只使用既有道路、方向、跨线、信号及指定路线格式；可导出、保存、编辑。四叶草使用四个象限的定向回环，左转先跨越中心再绕行；盘龙使用多跨线与定向匝道的简化拓扑，界面明确标注示意，不宣称真实比例或完整复刻。

界面通过原生 dialog 展示卡片库，用模型道路生成 SVG 缩略图；地图上方按钮在手机可见。只有点选案例才调用现有 edit 历史保存并重置模拟，浏览/关闭不替换地图。构建脚本包含新模块；快捷键在弹窗内不触发地图操作。

## 自动分流算法
随机出口仍从所有可达出口中等概率选择。没有指定行驶路线的入口，在发车前以有向边基础长度 + 当前在途/排队负载为代价进行 Dijkstra 搜索，考虑整个合法路网，而非每个出口预先冻结的一条 BFS 最短路。桥上的来向状态与单行限制同样参与搜索。候车期间可每 0.5 秒为同一出口重算自动路径，不重新抽出口；车辆一旦发出，路径固定。

### 2026-10-24 规则更新：自动车辆允许途中改道
用户确认只自动路线避堵，手画路线仍严格遵守；本条替代上述“车辆一旦发出，路径固定”。代价以秒计：每格行驶时间、当前车道负载/排队和按预计到达时刻计算的红灯等待相加。交通负载每0.5秒采样；Dijkstra支持起点来向、禁访已走节点和累计代价，以保留路口/桥层约束并预测信号等待。

车辆在路口前且未取得准入时比较剩余路线，当前路段、位置、已走前缀与目的地不变；新路线禁止回访已走节点。同一路口每份0.5秒负载快照只比较一次；节省至少2秒且超过原预计时间15%才切换，实际改道后冷却3秒。手画路线不参与重规划。记录实际改道次数供运行提示与交互验收。

路线管理沿用v1 routes数组，不迁移存档。源入口列表使用独立预览和删除按钮，编号按本入口显示；预览状态仅在界面内保存，不改变路网或暂停模拟。删除仅更新选中的数组项，经现有edit进入撤销、保存与重置流程。

已有明确指定路线的入口继续仅使用这些路线，绝不以自动避堵改变用户指定的途经点。界面说明自动车流按负载分流，虚线为当前可达出口示意，不代表唯一可行道路。

寻路状态保留进入桥节点的来向，避免把桥上桥下当成同一个可转弯路口；每个出口都独立得到真实可行的路线。桥节点不使用平面路口的互斥锁。SVG 依次绘制基础路面、桥下车辆、平直桥面、桥上车辆，使用上下遮挡表示跨线，取消圆形高亮和亮白护栏。桥面箭头来自真实道路方向，不固定画双向箭头。方向工具及其单向约束同时作用于桥上桥下道路。
